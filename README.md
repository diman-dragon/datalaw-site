# DataLaw Solutions — сайт юридической компании

Многостраничный сайт на Node.js + SQLite. **Внешних зависимостей нет**: `npm install` не нужен.
Нужен только Node.js 22.13 или новее.

## Запуск локально

```bash
cp .env.example .env      # при желании задайте ADMIN_PASSWORD
npm start
```

- Сайт: http://localhost:3000
- Админка: http://localhost:3000/admin/ (если пароль не задан, он напечатается в консоль при первом запуске)

База создаётся сама в `data/datalaw.sqlite` и заполняется стартовым контентом из `lib/seed-data.js`.

## Структура сайта

Главная, затем разделы в порядке меню: Арбитраж РФ, Гражданское право, Международное право, CRM «Лайла». Далее Новости и Контакты (форма, Telegram, WhatsApp, телефон, почта).

## Что в админке

- **Заявки**: форма с сайта попадает сюда; статусы (новая, в работе, закрыта, спам), заметки, выгрузка в CSV.
- **Направления**: тексты и список услуг каждого раздела.
- **Новости**: добавление и правка без кода.
- **Контакты**: телефон, почта, Telegram, WhatsApp, адрес, часы приёма (они же выводятся в шапке и подвале).

Чтобы заявки приходили в Telegram, заполните `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в `.env`.

## Публикация на GitHub Pages

GitHub Pages отдаёт только статику, поэтому там живёт витрина без базы. Сборку и публикацию делает GitHub сам (`.github/workflows/pages.yml`).

Первый раз:
1. Создайте на GitHub пустой репозиторий (без README).
2. В папке проекта выполните:
   ```bash
   git remote add origin https://github.com/ВАШ-ЛОГИН/ИМЯ-РЕПОЗИТОРИЯ.git
   git push -u origin main
   ```
3. В репозитории: Settings → Pages → Source: **GitHub Actions**.
   Запасной вариант, если Actions не используете: Source «Deploy from a branch», ветка `main`, папка `/docs`. Готовая сборка лежит в `docs/` и обновляется командой `npm run build`.
4. Через минуту сайт откроется на `https://ВАШ-ЛОГИН.github.io/ИМЯ-РЕПОЗИТОРИЯ/`. Адрес и пути подставляются автоматически.

Свой домен: в Settings → Pages укажите домен, а в workflow или через переменную добавьте `CNAME`.

### Как правки из админки попадают на GitHub

Контент сайта лежит в `content/site.json`. Изменили текст в админке локально, затем:
```bash
npm run export          # выгрузить контент из базы в content/site.json
git add content && git commit -m "Обновить контент" && git push
```
GitHub пересоберёт сайт. Заявки, пароли и секреты в этот файл не попадают.

### Форма на GitHub-версии

- без настроек откроется письмо в почтовой программе посетителя;
- чтобы заявки шли на ваш Node-сервер: в репозитории Settings → Secrets and variables → Actions → Variables добавьте `API_URL` = `https://ваш-сервер/api/lead`, а на сервере в `.env` задайте `ALLOWED_ORIGIN=https://ВАШ-ЛОГИН.github.io`.

## Переезд на хостинг

1. Выберите VPS или хостинг с Node.js 22.13+.
2. Клонируйте репозиторий. Контент подтянется из `content/site.json` при первом запуске.
3. Задайте в `.env`: `SITE_URL`, `ADMIN_PASSWORD`, `TRUST_PROXY=true` (если за nginx).
4. Запустите `npm start` под pm2 или systemd, поставьте перед ним nginx с HTTPS (Let's Encrypt).
5. Резервная копия: достаточно копировать `data/datalaw.sqlite`.

## Структура

```
server.js                сервер: страницы, API заявок, админка
lib/db.js                схема SQLite и запросы
lib/seed-data.js         стартовый контент
lib/pages.js             шаблоны публичных страниц
lib/layout.js            шапка, подвал, SEO-теги
lib/admin.js             страницы админки
lib/auth.js              вход, сессии, защита от подбора пароля
public/css/site.css      вся дизайн-система (цвета в :root)
scripts/build-static.js  сборка для GitHub Pages
scripts/export-content.js выгрузка контента из базы в content/site.json
content/site.json        контент сайта (хранится в git)
```

## Дизайн

Цвета сняты с эмблемы и заданы переменными в начале `public/css/site.css`: тёмно-синий `#12203F`, золото `#C4A04F` (только акцент), светлые серые для фона.
Шрифты: Cormorant (заголовки) и Golos Text (текст и интерфейс), подключены с Google Fonts. Для полной независимости от внешних сервисов скачайте их в `public/fonts/` и подключите через `@font-face`.

## Перед запуском проверьте

- Контакты в админке: телефон, почта, WhatsApp в seed — заглушки. Telegram взят из ваших материалов (datalaw_rights).
- Цифры в синей полосе на главной (1997, 4 языка, 24/7) взяты из ваших файлов, подтвердите их.
- Название «DataLaw International» взято с эмблемы. Если фирма называется иначе, поправьте в `lib/layout.js` и `lib/pages.js`.
- Четыре стартовые новости написаны как образцы (две из них практические разборы со ссылками на сроки). Проверьте и замените на свои.
- Текст политики конфиденциальности — шаблон, его должен проверить юрист.
